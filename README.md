# ReciPal

Node.js の標準モジュールと素の HTML/CSS/JavaScript だけで動くレシピ管理アプリです。npm パッケージは使っていません。

## 起動方法

- **Windows**：`ReciPal.bat` をダブルクリックすると、ブラウザが自動で開きます。
- **コマンドから**：`node server.js`（ブラウザを開かない場合は `node server.js --no-open`）

終了するには、黒いコンソールウィンドウを閉じるか、`Ctrl+C` を押します。
ReciPal が起動中にもう一度 `ReciPal.bat` を実行すると、既存のサーバーをブラウザで開くだけになります。

ポート 3000 が使用中の場合は 3001、3002… を順に試します。環境変数 `PORT` でポートを指定することもできます。

### 安全のための制限

ReciPal は自分の PC だけで使うアプリなので、次のアクセスは拒否します。

- `http://localhost:ポート` / `http://127.0.0.1:ポート` 以外のアドレスでのアクセス（DNS リバインディング対策）
- ほかのサイトからのデータの書き換え（Origin のチェック、更新系 API は `Content-Type: application/json` のみ受け付け）

## 機能

- レシピの追加・編集・削除
- 材料（材料名・分量）と手順の登録。行の追加・削除・並べ替えができます
- キーワード検索（レシピ名・説明・材料・手順・タグが対象。スペース区切りで AND 検索）
- カテゴリ・レシピの特徴（タグ）・使っている材料の分類（タグ）での絞り込み
- 材料マスタ（材料の名前・別名・タグを登録し、レシピから紐付け）
- タグ（レシピのタグ・材料のタグの 2 種類）
- 買い物リスト（レシピの材料をまとめて追加、売り場ごとに表示、テキストでコピー）
- 編集フォーム（レシピ・材料・タグ）は、内容を変更したまま Esc キー・キャンセル・✕ で閉じようとすると、破棄してよいか確認します
- 表示言語の切り替え（日本語 / 简体中文）。右上のセレクトで切り替え、選んだ言語はブラウザに保存されます。初回はブラウザの言語設定から自動で選びます

## バリエーション（人数別・作り方別）

1 つのレシピの中に、人数や作り方ごとの「バリエーション」を複数持てます。

- **共通の項目**：レシピ名・説明・カテゴリ
- **バリエーションごとの項目**：名前（任意。例：圧力鍋版）・人数・調理時間・材料・手順
- 詳細画面では、バリエーションをタブで切り替えます（2 つ以上あるときだけ表示）。
- 入力フォームの「このバリエーションをコピー」で、内容を丸ごと複製して新しいバリエーションを作れます。
- 分量の自動換算はしません。登録した内容をそのまま表示します。
- 旧形式のデータ（人数・材料・手順をレシピ直下に持つもの）は、読み込み時にバリエーション 1 つのレシピとして扱います。

```json
{
  "id": "...",
  "title": { "ja": "...", "zh": "..." },
  "description": { "ja": "...", "zh": "..." },
  "category": "main",
  "variants": [
    { "id": "v1", "label": {}, "servings": 2, "time": 30, "ingredients": [], "steps": [] }
  ],
  "createdAt": "...",
  "updatedAt": "..."
}
```

## 材料マスタ

ヘッダーの「材料」画面で、材料を登録・編集・削除できます。

- **項目**：材料名（言語ごと）・別名（言語ごと、検索用）・タグ
- **レシピとの紐付け**：レシピの材料名欄に、登録済みの材料が候補として出ます。
  - 名前か別名（どの言語でも）が一致すると自動で紐付き、行の左に ✓ が付きます。
  - 紐付けると、他の言語の材料名も自動で入ります。別名で入力した場合は、正式名に置き換わります。
  - 紐付いた材料は、レシピ表示時に材料マスタの名前（最新の翻訳）を使います。
- **自由入力も可能**：材料マスタにない名前もそのまま使えます。
  - 材料画面の「レシピから取り込む」で、未登録の材料をまとめて登録・紐付けできます。
  - 名前や別名が一致するものは、既存の材料に紐付けます。
- **削除**：使用中の材料を削除すると、レシピからは紐付けだけが外れます。レシピ上の名前（控え）は残ります。
- **自動移行**：材料マスタ導入前のデータで起動すると、既存レシピの材料から材料マスタを自動生成して紐付けます。

## タグ

ヘッダーの「タグ」画面で、タグを登録・編集・削除できます。タグには 2 つの種類があります。

| 種類 | 用途 | 例 | 付ける対象 |
|---|---|---|---|
| レシピのタグ（`recipe`） | 料理の特徴 | 時短・ベジタリアン | レシピ |
| 材料のタグ（`ingredient`） | 材料の分類 | 肉類・野菜・調味料 | 材料 |

- レシピのフォームにはレシピのタグだけ、材料のフォームには材料のタグだけが表示されます。
- レシピ一覧の絞り込みは 2 つの欄に分かれていて、組み合わせられます。
  - **特徴**：レシピに付いたタグで絞り込みます。
  - **材料**：その分類の材料（材料マスタに紐付いたもの）を使うレシピで絞り込みます。
  - 例：「特徴：時短」×「材料：野菜」
- タグの種類は作成時に決まり、後から変えられません。
- タグを削除すると、付いていたレシピまたは材料からも外れます。
- 種類のないタグ（以前のデータ）は、起動時に自動で振り分けます。レシピだけで使われていればレシピのタグ、それ以外は材料のタグになります。

## 買い物リスト

ヘッダー右上の「🛒 買い物」ボタンを押すと、画面の右側からパネルが開きます。どの画面からでも開けます。ボタンには「買う」品数が表示されます。リストは 1 つです。パネルは Esc キー、✕、背景のクリックで閉じます。

- **レシピから追加**：レシピ詳細の「🛒 買い物リストに追加」で、表示中のバリエーションの材料をすべて追加します。
  - 同じバリエーションをもう一度追加すると「×2」と表示されます。分量は換算しません。
- **買う / 買わない**：品目は最初からチェックが入った「買う」状態です。チェックを外すと、下の「**買わないもの**」に移ります（家にあるものなど）。
  - **常備品**（材料画面で印を付けたもの）は、レシピから追加したとき最初から「買わないもの」に入ります。
  - 同じバリエーションをもう一度追加すると、そのレシピの行が「買う」に戻ります。ただし常備品は今の状態のままです。
  - 手入力で追加したものは、常備品でも「買う」になります。
- **リストはレシピの材料行ごとに 1 行**です。同じ材料でもまとめず、隣り合わせに並べます。レシピごとに「買う / 買わない」を決められます（例：スープ分の玉ねぎは家にあるので外す）。
- 手入力は、同じ名前でも 1 件ずつ別の行になります。
- **手入力**：牛乳などレシピ以外の品目も追加できます。材料名の候補が出て、材料マスタと一致すれば紐付きます。
- **売り場ごとの表示**：「買う」品目を材料のタグ（名前順で最初のもの）でグループにします。タグがなければ「その他」です。
- ボタンの品数は、同じ材料を 1 品として数えます（コピーするテキストの行数と同じ）。
- **削除**：手入力の行は、右端の ✕ で 1 行ずつ削除できます（確認なし）。レシピの行は個別には削除できず、上部の対象レシピの ✕ でそのレシピ分をまとめて外します。「すべて削除」もあります。
  - 手入力の行には、レシピ名の位置に「手入力」と表示されます。
- 「テキストでコピー」は「買う」品目がないとき、「すべて削除」は品目が 1 件もないときに押せなくなります。
- 同じレシピを 2 回以上追加した行は、分量の後ろに「×2」のバッジが付きます。
- **テキストでコピー**：「買う」品目を、売り場ごとのテキストとしてクリップボードにコピーします。LINE やメモアプリに貼ってスマホで使えます。
  - 同じ材料（材料マスタの ID、または名前の一致で判定）は 1 行にまとめ、分量だけを並べます。例：`・玉ねぎ 2個×2 ＋ 1個`
  - `×2` は同じレシピを 2 回追加した分です。分量の合算はしません。数量なしの行は省きます。
- 分量や名前は追加した時点の控えです。あとでレシピを編集しても、リストは変わりません。
- 品目データの `skip: true` が「買わないもの」です。以前の形式（`checked`、同じ材料を 1 行にまとめた `entries`）は、読み込み時に今の形式に変換します。

## 多言語対応

- 画面の文言は `public/i18n.js` の `MESSAGES` にまとめています。言語を追加するときは、`LANGUAGES` と `MESSAGES` に同じキーで追加してください。
- 既定カテゴリはデータ上 `main` / `side` / `soup` / `staple` / `dessert` / `other` のキーで保存し、表示時に翻訳します。どの言語の表示名を入力しても同じキーとして保存されます。ユーザーが自由に入力したカテゴリはそのまま保存されます。
- レシピの中身（レシピ名・説明・材料名・分量・手順）は言語ごとに保存します。形式は `{ "ja": "...", "zh": "..." }` です。
  - 入力フォーム上部の「入力言語」タブで、入力する言語を切り替えます。材料と手順の行はすべての言語で共通です。
  - 空欄には、他の言語で入力済みの内容が薄く表示されます。レシピ名はどれか 1 つの言語で入力すれば保存できます。
  - 表示言語の訳がない項目は、他の言語で斜体表示し、「未翻訳」と分かるようにします。
  - キーワード検索は、すべての言語のテキストが対象です。
  - 旧形式（文字列）のデータも読み込めます。日本語として扱われます。
- サーバーはエラーを `code`（例：`TITLE_REQUIRED`）で返し、画面側で翻訳します。

## データ

| ファイル | 内容 |
|---|---|
| `data/recipes.json` | レシピ |
| `data/ingredients.json` | 材料マスタ |
| `data/tags.json` | タグ |
| `data/shopping.json` | 買い物リスト（最初に追加したときに作成） |

- `data` フォルダやファイルがないときは、起動時に空のファイルを作成します（レシピ・材料・タグが 0 件の状態で始まります）。
- バックアップを取るときは、`data` フォルダごとコピーしてください。

レシピの材料行は、材料マスタに紐付く場合 `ingredientId` を持ちます。`name` は表示用の控えです。

```json
{ "ingredientId": "ing-onion", "name": { "ja": "玉ねぎ", "zh": "洋葱" }, "amount": { "ja": "1個", "zh": "1个" } }
```

材料の形式：

```json
{ "id": "ing-onion", "name": { "ja": "玉ねぎ", "zh": "洋葱" }, "aliases": { "ja": ["たまねぎ"] }, "tags": ["tag-vegetable"], "pantry": false }
```

タグの形式：

```json
{ "id": "tag-quick", "type": "recipe", "name": { "ja": "時短", "zh": "快手" } }
```

## ファイル構成

```
ReciPal.bat              ダブルクリックで起動
server.js                HTTP サーバーと REST API（http / fs / path / crypto のみ）
data/                    保存データ（自動生成）
public/
  index.html
  style.css
  i18n.js                翻訳辞書と言語切り替え
  js/main.js             画面の切り替え・初期化（ES モジュール）
  js/common.js           API・DOM 部品・多言語入力欄・データストア
  js/recipes.js          レシピ画面
  js/ingredients.js      材料画面
  js/tags.js             タグ画面
  js/shopping.js         買い物リスト（右から開くパネル）
```

## API

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/recipes` | 一覧 |
| GET | `/api/recipes/:id` | 1 件取得 |
| POST | `/api/recipes` | 追加 |
| PUT | `/api/recipes/:id` | 更新 |
| DELETE | `/api/recipes/:id` | 削除 |

`/api/ingredients` と `/api/tags` も同じ形です。このほかに次の API があります。

| メソッド | パス | 内容 |
|---|---|---|
| POST | `/api/ingredients/import` | レシピの未登録の材料を材料マスタに取り込み、紐付ける |

買い物リスト（更新系はすべてリスト全体を返します）：

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/shopping` | リスト全体 |
| POST | `/api/shopping/recipes` | レシピの材料をすべて追加（`{ recipeId, variantId }`）。常備品は「買わないもの」に入る |
| DELETE | `/api/shopping/recipes/:recipeId/:variantId` | そのレシピ分を取り除く |
| POST | `/api/shopping/items` | 手入力で追加（`{ name, amount, ingredientId? }`） |
| PATCH | `/api/shopping/items/:id` | 「買う / 買わない」の切り替え（`{ skip }`） |
| DELETE | `/api/shopping/items/:id` | 手入力の行を削除（レシピの行を指定すると `ITEM_NOT_DELETABLE` エラー） |
| POST | `/api/shopping/clear` | すべて削除 |
