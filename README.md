# ReciPal

Node.js の標準モジュールと素の HTML/CSS/JavaScript だけで動くレシピ管理アプリです。npm パッケージは使っていません。

## 起動方法

- **Windows**：`ReciPal.bat` をダブルクリックすると、ブラウザが自動で開きます。
- **コマンドから**：`node server.js`（ブラウザを開かない場合は `node server.js --no-open`）

終了するには、黒いコンソールウィンドウを閉じるか、`Ctrl+C` を押します。
ReciPal が起動中にもう一度 `ReciPal.bat` を実行すると、既存のサーバーをブラウザで開くだけになります。

ポート 3000 が使用中の場合は 3001、3002… を順に試します。環境変数 `PORT` でポートを指定することもできます。

### 安全のための制限

ReciPal は自分の PC だけで使うアプリなので、次のアクセスは拒否します。

- `http://localhost:ポート` / `http://127.0.0.1:ポート` 以外のアドレスでのアクセス（DNS リバインディング対策）
- ほかのサイトからのデータの書き換え（Origin のチェック、更新系 API は `Content-Type: application/json` のみ受け付け）

## 機能

- レシピの追加・編集・削除
- 材料（材料名・分量）と手順の登録。行の追加・削除・並べ替えができます
- キーワード検索（レシピ名・説明・材料・手順・タグが対象。スペース区切りで AND 検索）
- カテゴリ・レシピの特徴（タグ）・使っている材料の分類（タグ）での絞り込み
- 材料マスタ（材料の名前・別名・タグを登録し、レシピから紐付け）
- タグ（レシピのタグ・材料のタグの 2 種類）
- 買い物リスト（レシピの材料をまとめて追加、売り場ごとに表示、テキストでコピー）
- 編集フォーム（レシピ・材料・タグ）は、内容を変更したまま Esc キー・キャンセル・✕ で閉じようとすると、破棄してよいか確認します
- 表示言語の切り替え（日本語 / 简体中文 / English）。右上のセレクトで切り替え、選んだ言語はブラウザに保存されます。初回はブラウザの言語設定から自動で選びます
- データの言語の設定（日本語 / 简体中文 / English から選択）。レシピ・材料・タグを、表示言語とは別の言語の組み合わせで登録できます

## バリエーション（人数別・作り方別）

1 つのレシピの中に、人数や作り方ごとの「バリエーション」を複数持てます。

- **共通の項目**：レシピ名・説明・カテゴリ
- **バリエーションごとの項目**：名前（任意。例：圧力鍋版）・人数・調理時間・材料・手順
- 詳細画面では、バリエーションをタブで切り替えます（2 つ以上あるときだけ表示）。
- 入力フォームの「このバリエーションをコピー」で、内容を丸ごと複製して新しいバリエーションを作れます。
- 分量の自動換算はしません。登録した内容をそのまま表示します。
- 旧形式のデータ（人数・材料・手順をレシピ直下に持つもの）は、読み込み時にバリエーション 1 つのレシピとして扱います。

```json
{
  "id": "...",
  "title": { "ja": "...", "zh": "..." },
  "description": { "ja": "...", "zh": "..." },
  "category": "main",
  "variants": [
    { "id": "v1", "label": {}, "servings": 2, "time": 30, "ingredients": [], "steps": [] }
  ],
  "createdAt": "...",
  "updatedAt": "..."
}
```

## 材料マスタ

ヘッダーの「材料」画面で、材料を登録・編集・削除できます。

- **項目**：材料名（言語ごと）・別名（言語ごと、検索用）・タグ
- **レシピとの紐付け**：レシピの材料名欄に、登録済みの材料が候補として出ます。
  - 名前か別名（どの言語でも）が一致すると自動で紐付き、行の左に ✓ が付きます。
  - 紐付けると、他の言語の材料名も自動で入ります。別名で入力した場合は、正式名に置き換わります。
  - 紐付いた材料は、レシピ表示時に材料マスタの名前（最新の翻訳）を使います。
- **自由入力も可能**：材料マスタにない名前もそのまま使えます。
  - 材料画面の「レシピから取り込む」で、未登録の材料をまとめて登録・紐付けできます。
  - 名前や別名が一致するものは、既存の材料に紐付けます。
  - 取り込む前に確認画面が開き、「新しく登録する材料」と「登録済みの材料に紐付ける」に分けて一覧表示します。
    - 新規登録：材料名（各言語）と、それを使っているレシピ名
    - 紐付け：紐付ける先の材料と、追加される名前・別名（例：「鶏もも肉」に別名「とりもも肉」を追加）
  - チェックを外した材料は取り込みません（レシピ側も紐付けないまま残ります）。表記ゆれや誤入力は、外してからレシピを直してください。
  - 取り込んだ材料は、一覧で数秒間だけ色付きで表示されます。
- **削除**：使用中の材料を削除すると、レシピからは紐付けだけが外れます。レシピ上の名前（控え）は残ります。
- **自動移行**：材料マスタ導入前のデータで起動すると、既存レシピの材料から材料マスタを自動生成して紐付けます。

## タグ

ヘッダーの「タグ」画面で、タグを登録・編集・削除できます。タグには 2 つの種類があります。

| 種類 | 用途 | 例 | 付ける対象 |
|---|---|---|---|
| レシピのタグ（`recipe`） | 料理の特徴 | 時短・ベジタリアン | レシピ |
| 材料のタグ（`ingredient`） | 材料の分類 | 肉類・野菜・調味料 | 材料 |

- レシピのフォームにはレシピのタグだけ、材料のフォームには材料のタグだけが表示されます。
- レシピ一覧の絞り込みは 2 つの欄に分かれていて、組み合わせられます。
  - **特徴**：レシピに付いたタグで絞り込みます。
  - **材料**：その分類の材料（材料マスタに紐付いたもの）を使うレシピで絞り込みます。
  - 例：「特徴：時短」×「材料：野菜」
- タグの種類は作成時に決まり、後から変えられません。
- タグを削除すると、付いていたレシピまたは材料からも外れます。
- 種類のないタグ（以前のデータ）は、起動時に自動で振り分けます。レシピだけで使われていればレシピのタグ、それ以外は材料のタグになります。

## 買い物リスト

ヘッダー右上の「🛒 買い物」ボタンを押すと、画面の右側からパネルが開きます。どの画面からでも開けます。ボタンには「買う」品数が表示されます。リストは 1 つです。パネルは Esc キー、✕、背景のクリックで閉じます。

- **レシピから追加**：レシピ詳細の「🛒 買い物リストに追加」で、表示中のバリエーションの材料をすべて追加します。
  - 同じバリエーションをもう一度追加すると「×2」と表示されます。分量は換算しません。
- **買う / 買わない**：品目は最初からチェックが入った「買う」状態です。チェックを外すと、下の「**買わないもの**」に移ります（家にあるものなど）。
  - **常備品**（材料画面で印を付けたもの）は、レシピから追加したとき最初から「買わないもの」に入ります。
  - 同じバリエーションをもう一度追加すると、そのレシピの行が「買う」に戻ります。ただし常備品は今の状態のままです。
  - 手入力で追加したものは、常備品でも「買う」になります。
- **リストはレシピの材料行ごとに 1 行**です。同じ材料でもまとめず、隣り合わせに並べます。レシピごとに「買う / 買わない」を決められます（例：スープ分の玉ねぎは家にあるので外す）。
- 手入力は、同じ名前でも 1 件ずつ別の行になります。
- **手入力**：牛乳などレシピ以外の品目も追加できます。材料名の候補が出て、材料マスタと一致すれば紐付きます。
- **売り場ごとの表示**：「買う」品目を材料のタグ（名前順で最初のもの）でグループにします。タグがなければ「その他」です。
- ボタンの品数は、同じ材料を 1 品として数えます（コピーするテキストの行数と同じ）。
- **削除**：手入力の行は、右端の ✕ で 1 行ずつ削除できます（確認なし）。レシピの行は個別には削除できず、上部の対象レシピの ✕ でそのレシピ分をまとめて外します。「すべて削除」もあります。
  - 手入力の行には、レシピ名の位置に「手入力」と表示されます。
- 「テキストでコピー」は「買う」品目がないとき、「すべて削除」は品目が 1 件もないときに押せなくなります。
- 同じレシピを 2 回以上追加した行は、分量の後ろに「×2」のバッジが付きます。
- **テキストでコピー**：「買う」品目を、売り場ごとのテキストとしてクリップボードにコピーします。LINE やメモアプリに貼ってスマホで使えます。
  - 同じ材料（材料マスタの ID、または名前の一致で判定）は 1 行にまとめ、分量だけを並べます。例：`・玉ねぎ 2個×2 ＋ 1個`
  - `×2` は同じレシピを 2 回追加した分です。分量の合算はしません。数量なしの行は省きます。
- 分量や名前は追加した時点の控えです。あとでレシピを編集しても、リストは変わりません。
- 品目データの `skip: true` が「買わないもの」です。以前の形式（`checked`、同じ材料を 1 行にまとめた `entries`）は、読み込み時に今の形式に変換します。

## 多言語対応

言語には「表示言語」と「データの言語」の 2 種類があります。

| 種類 | 内容 | 選べる言語 | 変更方法 | 保存先 |
|---|---|---|---|---|
| 表示言語 | ボタンや見出しなど、画面の文言の言語 | 日本語・简体中文・English | 右上のセレクト | ブラウザ |
| データの言語 | レシピ・材料・タグの入力フォームに出す言語 | 日本語・简体中文・English | 右上の ⚙ 設定 | `data/settings.json` |

選べる言語は、表示言語とデータの言語で同じです。

### データの言語

- 例：表示は日本語のまま、データは「日本語と英語」で登録する、といった使い方ができます。
- 入力フォーム上部の「入力言語」タブには、設定で選んだ言語だけが出ます。
- フォームを開いたときは、表示言語がデータの言語にあればその言語、なければ最初のデータの言語のタブを選びます。買い物リストの手入力も同じ言語で保存します。
- 設定画面では、それぞれの言語で登録済みのデータがあるレシピ・材料・タグの件数を表示します。
- チェックを外した言語のデータは消えません。フォームで編集・保存しても残ります。表示言語の訳がない項目では、その言語で表示されます。
- 設定ファイルがないとき（以前のデータ）は、日本語と简体中文を使います。
- 表示言語を追加すると、データの言語にも自動で追加されます。画面を翻訳せずにデータだけ使える言語を増やすときは、`public/i18n/i18n.js` の `DATA_LANGUAGES` に追加します。
- `DATA_LANGUAGES` にない言語のデータ（JSON に手で書いたものなど）は、フォームで保存すると消えます。
- 設定ファイルに一覧にない言語（以前の `ko` など）が残っていても無視します。

### 表示言語

- 画面の文言は、言語ごとに `public/i18n/locales/<言語コード>.json` に「翻訳キー: 翻訳値」の形で置いています（`ja.json` / `zh.json` / `en.json`）。起動時にすべての言語を読み込みます。
- 表示を切り替える処理は `public/i18n/i18n.js` にあります。
- **表示言語を追加するとき**：
  1. `ja.json` をコピーして `public/i18n/locales/<言語コード>.json` を作り、値を翻訳する（キーは変えない）
  2. `public/i18n/i18n.js` の `LANGUAGES` に 1 行追加する（ブラウザからはフォルダの中身を一覧できないため）
  3. `node scripts/check-i18n.js` でキーの漏れがないか確かめる
- **文言を追加・変更するとき**も、すべての言語の JSON を同じキーで更新し、`node scripts/check-i18n.js` で確かめてください。次の点をチェックします。
  - `LANGUAGES` の言語ごとに JSON があるか、JSON の形式が正しいか
  - 日本語（基準）と同じキーがそろっているか
  - `{n}` などの差し込み箇所が日本語と同じか
  - HTML・JS で使っている翻訳キーが日本語の JSON にあるか
- 数で形が変わる文言（英語の単数・複数など）は `{ "one": "1 recipe", "other": "{n} recipes" }` のように書くと、`{n}` の値で選ばれます（`Intl.PluralRules` を使用）。
- 区切り記号（「、」「・」「【】」など）も言語ごとに違うので、JS に直接書かずに JSON に入れています（例：`common.listSeparator`、`shopping.copyGroup`）。
- 文言が見つからない言語では、日本語の文言を表示します。
- JSON を読み込めないときは、画面の上部にエラー（ファイル名と原因）を表示します。読み込めた言語は今までどおり使えます。
- 既定カテゴリはデータ上 `main` / `side` / `soup` / `staple` / `dessert` / `other` のキーで保存し、表示時に翻訳します。どの言語の表示名を入力しても同じキーとして保存されます。ユーザーが自由に入力したカテゴリはそのまま保存されます。
- レシピの中身（レシピ名・説明・材料名・分量・手順）は言語ごとに保存します。形式は `{ "ja": "...", "zh": "..." }` です。
  - 入力フォーム上部の「入力言語」タブで、入力する言語を切り替えます。材料と手順の行はすべての言語で共通です。
  - 空欄には、他の言語で入力済みの内容が薄く表示されます。レシピ名はどれか 1 つの言語で入力すれば保存できます。
  - 表示言語の訳がない項目は、他の言語で斜体表示します。
    - レシピ一覧のカード・材料一覧・タグ一覧・材料の取り込み画面では、名前の横に「未翻訳」を表示します。
    - レシピ詳細では、上部に「この言語の翻訳がない項目は、〇〇で表示しています。」と表示します。
    - 買い物リストでは、品目名・対象レシピ名・売り場名（材料のタグ）を斜体にします。
    - 材料一覧・タグ一覧で名前の下に並べる他の言語の名前は、代わりに表示している言語の分を省きます（同じ名前が 2 回出ないように）。
  - キーワード検索は、すべての言語のテキストが対象です。
  - 旧形式（文字列）のデータも読み込めます。日本語として扱われます。
- サーバーはエラーを `code`（例：`TITLE_REQUIRED`）で返し、画面側で翻訳します。

## データ

| ファイル | 内容 |
|---|---|
| `data/recipes.json` | レシピ |
| `data/ingredients.json` | 材料マスタ |
| `data/tags.json` | タグ |
| `data/shopping.json` | 買い物リスト（最初に追加したときに作成） |
| `data/settings.json` | 設定（データの言語）。最初に設定を保存したときに作成 |

- `data` フォルダやファイルがないときは、起動時に空のファイルを作成します（レシピ・材料・タグが 0 件の状態で始まります）。
- `data` フォルダは Git で管理していません（`.gitignore`）。自分のレシピなどのデータが、コミットや push で GitHub に公開されないようにするためです。
- Git の履歴には残りません。毎日の自動バックアップ（下の「バックアップ」）のほかに、自分でも残したいときは `data` フォルダごとコピーしてください。

レシピの材料行は、材料マスタに紐付く場合 `ingredientId` を持ちます。`name` は表示用の控えです。

```json
{ "ingredientId": "ing-onion", "name": { "ja": "玉ねぎ", "zh": "洋葱" }, "amount": { "ja": "1個", "zh": "1个" } }
```

材料の形式：

```json
{ "id": "ing-onion", "name": { "ja": "玉ねぎ", "zh": "洋葱" }, "aliases": { "ja": ["たまねぎ"] }, "tags": ["tag-vegetable"], "pantry": false }
```

タグの形式：

```json
{ "id": "tag-quick", "type": "recipe", "name": { "ja": "時短", "zh": "快手" } }
```

## バックアップ

その日に初めてデータ（レシピ・材料・タグ・買い物リスト・設定）を保存する直前に、`data` フォルダの内容を自動でコピーします。**その日の変更前の状態** が残るので、間違えて削除・上書きしたときに戻せます。

- **保存先**：既定は ReciPal のフォルダの中の `backup` フォルダです（`data` の隣。Git では管理しません）。
- **形式**：`backup\recipal-2026-11-24\` のように、日付ごとのフォルダに `data` の JSON をそのままコピーします。
- **残す数**：新しいものから 7 日分です。古いものは自動で削除します。削除するのは `recipal-YYYY-MM-DD` という名前のフォルダだけで、保存先にあるほかのファイルには触れません。
- **取らないとき**：まだデータがないとき（初回起動）は取りません。その日の分がすでにあるとき（同じ日に ReciPal を起動し直したときなど）は、上書きしません。
- **失敗したとき**：データの保存は止めずに続けます。原因は、黒いコンソールウィンドウと設定画面に表示します。
- **状態の確認**：右上の ⚙ 設定の「バックアップ」に、保存先と最後のバックアップの日時を表示します（ここでは変更できません）。

### 保存先を変える

別のドライブや OneDrive のフォルダに保存すると、PC やディスクの故障にも備えられます。保存先は、Windows の環境変数 `RECIPAL_BACKUP_DIR` で指定します（画面からは変えられません）。

- **設定画面から**：スタートメニューで「環境変数」と検索し、「環境変数を編集」（ユーザー環境変数）を開きます。「新規」で、変数名に `RECIPAL_BACKUP_DIR`、値に保存先のフォルダ（例：`D:\Backup\ReciPal`）を入力します。
- **コマンドから**：コマンドプロンプトで次を実行します。
  ```bat
  setx RECIPAL_BACKUP_DIR "D:\Backup\ReciPal"
  ```
- 設定したら、ReciPal を閉じて起動し直してください（開いたままのウィンドウには反映されません）。
- フォルダがなければ自動で作ります。日本語やスペースを含むパスも使えます。
- 次の場所は使えません（指定するとバックアップを取りません）：`data` や `public` の中、`backup` 以外の ReciPal のフォルダの中。
- Mac や Linux では、シェルの設定ファイル（`~/.zshrc` など）に `export RECIPAL_BACKUP_DIR=...` と書きます。

### バックアップから戻す

1. ReciPal を終了する
2. 念のため、今の `data` フォルダを別の場所にコピーしておく
3. 戻したい日のフォルダ（例：`backup\recipal-2026-11-24`）の中のファイルを、`data` フォルダにコピーして上書きする
4. ReciPal を起動する

戻したい日のフォルダには、その日の変更前の状態が入っています。たとえば 11 月 24 日に間違えて削除したなら、`recipal-2026-11-24` を戻します。

## テスト

Node.js に標準で入っているテストの機能（`node:test`）を使っています。追加のインストールは要りません。ReciPal のフォルダで次を実行します。

```bat
node --test
```

- 変更したら、コミットの前に実行してください。最後に `# fail 0` と出れば問題ありません。
- テストは、一時フォルダにプログラムをコピーし、テスト用のデータでサーバーを起動して確かめます。**自分の `data`・`backup` には触れません。** 環境変数 `RECIPAL_BACKUP_DIR` や `PORT` を設定していても、テストでは使いません。
- 対象：レシピ・材料・タグの API、材料の取り込み、買い物リスト、自動バックアップ、起動時の処理（初回起動・以前の形式からの移行）、アクセス制限、設定、画面の文言（`scripts/check-i18n.js` も一緒に実行されます）
- 画面（ブラウザ）の操作はテストしていません。画面を変えたときは、ブラウザで動作を確かめてください。
- **自動実行**：GitHub に push したとき（`main` とプルリクエスト）、GitHub Actions が Linux と Windows でテストを実行します（`.github/workflows/test.yml`）。結果はプルリクエストの画面に ✓ / ✕ で表示されます。✕ のときは「Details」から失敗したテストを確認できます。
- テストを追加するときは、`test/` に `〇〇.test.js` という名前で置きます。サーバーの起動は `test/helpers/server.js` の `startServer()` を使います。

## API

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/recipes` | 一覧 |
| GET | `/api/recipes/:id` | 1 件取得 |
| POST | `/api/recipes` | 追加 |
| PUT | `/api/recipes/:id` | 更新 |
| DELETE | `/api/recipes/:id` | 削除 |

`/api/ingredients` と `/api/tags` も同じ形です。このほかに次の API があります。

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/settings` | 設定（`{ "dataLanguages": ["ja", "en"] }`） |
| GET | `/api/backup` | バックアップの状態（保存先・最後のバックアップの日時・エラー）。変更はできない |
| PUT | `/api/settings` | 設定の保存。`dataLanguages` が空なら `DATA_LANGUAGES_REQUIRED` エラー |
| GET | `/api/ingredients/import` | 取り込み内容のプレビュー（データは変更しない） |
| POST | `/api/ingredients/import` | レシピの未登録の材料を材料マスタに取り込み、紐付ける。`{ keys: [...] }` でプレビューのグループを選べる（省略時はすべて） |

取り込みの結果（プレビューも同じ形）：

```json
{
  "created": 1,
  "linked": 3,
  "groups": [
    { "key": "new:ja:ベーコン", "action": "create", "ingredientId": "...", "name": { "ja": "ベーコン" },
      "addedNames": { "ja": "ベーコン" }, "addedAliases": {}, "recipeIds": ["..."], "rows": 2 },
    { "key": "link:ing-chicken", "action": "link", "ingredientId": "ing-chicken", "name": { "ja": "鶏もも肉" },
      "addedNames": {}, "addedAliases": { "ja": ["とりもも肉"] }, "recipeIds": ["..."], "rows": 1 }
  ]
}
```

- `key` は登録・紐付けする先の材料ごとのグループの識別子です。同じデータなら毎回同じ値になります（新規：`new:<言語>:<名前>`、紐付け：`link:<材料 ID>`）。
- プレビューの `ingredientId`（新規分）は仮の値です。実際の ID は POST の結果を使ってください。

買い物リスト（更新系はすべてリスト全体を返します）：

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/shopping` | リスト全体 |
| POST | `/api/shopping/recipes` | レシピの材料をすべて追加（`{ recipeId, variantId }`）。常備品は「買わないもの」に入る |
| DELETE | `/api/shopping/recipes/:recipeId/:variantId` | そのレシピ分を取り除く |
| POST | `/api/shopping/items` | 手入力で追加（`{ name, amount, ingredientId? }`） |
| PATCH | `/api/shopping/items/:id` | 「買う / 買わない」の切り替え（`{ skip }`） |
| DELETE | `/api/shopping/items/:id` | 手入力の行を削除（レシピの行を指定すると `ITEM_NOT_DELETABLE` エラー） |
| POST | `/api/shopping/clear` | すべて削除 |
